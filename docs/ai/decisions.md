# AI module — decisions

What was decided for the AI module, when, and why. `AIplan.md` follows these; if the two disagree, this file wins and
the plan is corrected. Add a row whenever a default is tuned, an assumption is made or the plan is departed from.
Metrics quoted here come from a committed file under `eval/results/`, or are `TBD`.

## Design (grilling session, 2026-10-09)

| # | Date | Decision | Reason | Rejected |
|---|---|---|---|---|
| G1 | 2026-10-09 | **The Copilot is an upgrade to AI-01 (technician assistant), not a separate panel.** AI-01's suggested checks gain citations to manual sections. | AI-01 reasons only from the job's history and the model's general knowledge; it knows nothing a manufacturer wrote (error-code meanings, isolation steps, values). Grounding it reuses the endpoint, `AssistantPanel`, and tests, and avoids two overlapping technician AI features. | A second "Copilot" feature beside AI-01. |
| G2 | 2026-10-09 | **Every check is labelled by source** (refined by G12–G14). **A safety step without a valid manual citation is never shown**: the answer says no procedure is on file and to contact a Manager. Escalation is that message only. | Keeps AI-01 useful for equipment without a manual while making hallucinated safety procedures impossible to show, and it is testable. A work-order "escalated" flag would change non-AI features. | Refuse everything without evidence (useless on older equipment); citations only where found (no hallucination guarantee); a work-order flag. |
| G3 | 2026-10-09 | **Documents are tagged with a brand and one or more models.** Matching normalises both sides (upper case, spaces and dashes removed: `kb-10t` → `KB10T`) against `Equipment.Brand`/`Model`. Equipment with no model is searched without the equipment filter and the answer says the model is unknown. | Filters out other equipment's manuals without changing the domain model for an AI feature. A real `EquipmentModel` table becomes worthwhile if a manufacturer catalogue is ever imported. | An `EquipmentModel` table (about a week of non-AI change); no filter. |
| G4 | 2026-10-09 | **Embeddings are stored in SQL as bytes and searched in memory** (brute-force cosine) behind `IVectorStore`, cached for 5 minutes and invalidated after ingestion. Each chunk records the embedding model that produced it. Embeddings come from Gemini through the OpenAI-compatible `/embeddings` endpoint; the exact model is chosen and recorded in AI-1 (check Google's current list; `gemini-embedding-001` was the expected choice). | About 200–500 chunks × 768 dimensions is well under a millisecond to scan, and needs no new infrastructure. Local Docker runs SQL Server 2022, which has no `VECTOR` type. | SQL Server 2025 `VECTOR` (changes the database for the whole app); a separate vector database. |
| G5 | 2026-10-09 | **The evaluation set is split**: about 25 *dev* questions for tuning and 15+ *test* questions run once, at the end, and reported as they come. Results are reported as counts ("13/15"), dev and test side by side. Questions are written the way a technician talks (including Bahasa Malaysia, mixed terms, typos), not in the manual's words. AI may draft the knowledge-base documents; the owner writes the questions without studying the documents line by line. | Tuning and reporting on the same questions overstates quality; questions that copy the manual's wording make keyword search look perfect and never test the embeddings. With 15 questions each is ~7 points, so percentages would look more precise than the data. | One shared set; AI-generated questions. |
| G6 | 2026-10-09 | **Only manuals are retrieved.** No field-report documents, redaction service or source weights. Instead AI-01's `pastCases` widens from the same unit to **the same brand + model across all customers** (normalised as in G3). | `pastCases` already *are* field reports, from real data, and the context builder never selects customer name, contact, serial or location. Data minimisation is stronger than regex redaction. | Synthetic field reports + redaction; embedding completed work orders (sync cost, cross-customer leak risk). |
| G7 | 2026-10-09 | **Keyword retrieval is BM25 in memory**, built from the same cached chunks as the vectors. The tokenizer keeps identifiers (`E14`, `NC-450`, part numbers) whole and normalises them as in G3. `HasExactTermMatch` = an identifier in the question matched a chunk. The owner writes BM25 by hand. | Works for ordinary words ("lockout", "kondenser") as well as codes, with no new table. | The `AiChunkTerm` regex term table (blind to questions without codes); SQL full-text (not in the `mssql/server:2022` image, and its word breaker splits `NC-450`). |
| G8 | 2026-10-09 | **Documents are code.** `knowledge-base/*.md` with front matter (`slug`, `title`, `brand`, `models`, `version`, `supersedes`), changed by pull request. One ingestion service skips unchanged files by content hash, re-chunks and re-embeds changed ones, and hides superseded documents; it is called at Development startup, by a CLI command for deployments, and by the evaluation runner. | Nothing reaches the model without code review; one code path serves three callers; saves about a week of upload plumbing. Manual text is still treated as untrusted (a prompt-injection fixture stays in the knowledge base). | An upload API and admin screen (a next step). |
| G9 | 2026-10-09 | **The evaluation caches embeddings on disk**, keyed by (embedding model, SHA-256 of the chunk text), committed under `eval/cache/`. Chat responses are stored raw in the results file with the prompt version and model, and only regenerated when either changes. No evaluation in CI. | Retrieval scores become exactly reproducible without an API key; free-tier rate limits stop mattering after the first run; any changed number traces to a changed input. About 1.5 MB per chunking configuration. | Live calls every run (drift, rate limits); a nightly CI run (cost, a secret in CI). |
| G10 | 2026-10-09 | **Monitoring is "log everything, show a little"**: an `AiInteraction` row for every question (including failures), Helpful / Not helpful feedback, one "AI assistant" card on the Manager dashboard (questions this month, % refused, % helpful, p95 latency, estimated cost), and an Admin-only list endpoint with no page. **Interaction rows are deleted after 90 days** by a timer like `OrphanFileCleanupService`. | The log is what makes a bad answer debuggable; the full admin page is about a week, mostly charts. The stored question text may contain personal data, so it has a retention period. | The full admin metrics page; logging only. |
| G11 | 2026-10-09 | **Build a thin end-to-end slice first**: v1 = manuals → chunker → vector-only retrieval → AI-01 with citations → citation viewer → small evaluation. v2 adds BM25 + RRF **as a measured improvement** (evaluation before and after). v3 adds abstention, logging, feedback, the dashboard card and the README. | Ready to demo after about two weeks, and hybrid search is justified by the project's own before/after numbers rather than assumed. | Layer by layer (nothing to show until the end); evaluation first. |
| G12 | 2026-10-09 | **Three sources.** Each check's `source` is `Manual`, `History` or `General` (capitalised like the existing `likelihood` values). `General` is a simple, non-hazardous suggestion from general knowledge, shown as "General suggestion — not from a manual". A `Manual` check with no valid citation becomes `General`, never `History`. Manual sections reach the model with short per-request IDs (`M1`–`M5`) that the server maps to chunk IDs; chunk IDs never go to the model. | Keeps AI-01 useful for equipment with no manual and no history, without passing general knowledge off as documented. Relabelling to `History` would claim a past job the model never named. Short IDs cost fewer tokens, are easier for the model to copy exactly, and are trivial to validate. | Two sources (an uncited check had nowhere honest to go); chunk IDs in the prompt. |
| G13 | 2026-10-09 | **Deterministic safety backstop.** A check is a safety step if the model sets `isSafetyStep` **or** `SafetyTerms` matches its text (English and Malay, case-insensitive, whole words and phrases). A safety step that is not `Manual` with at least one valid section ID is removed, and the "contact a Manager" notice is shown. `SafetyTerms` is a static, unit-tested list in code, not configuration — an exception to the plan's configuration rule, so a deployment setting cannot switch the backstop off. False positives are acceptable; false negatives are not. | The model is never the only judge of risk: a model that forgets the flag still cannot show an uncited isolation or pressure step. | Trusting the model's flag alone; a configurable list. |
| G14 | 2026-10-09 | **History references are verified.** Each `History` check carries `workOrderIds`; IDs not in this request's `pastCases` are dropped, and a `History` check left with none becomes `General`. | The same rule `TechnicianAssistantOutput` already applies to `relevantPastCases`: the model cannot point a technician at a job it was never shown. Dropping bad items rather than refusing the answer also matches its existing behaviour. | Refusing the whole answer on one bad ID. |
| G15 | 2026-10-09 | **Ingestion handles removed files and chunking changes** (from v1.2 §3.3). A document whose file is no longer in `knowledge-base/` is marked `Removed` and is never retrieved, like a superseded one. A file is skipped only when its content hash **and** the chunking configuration both match what is stored. | Without the first, deleting a manual leaves it searchable. Without the second, the evaluation's 250/40 vs 400/50 comparison would skip unchanged files and compare the same chunks twice. | Hash-only skipping; deleting rows by hand. |
| G16 | 2026-10-09 | **Evidence gate on each chunk** (from v1.2 §5.3). After ranking, a chunk is sent to the model only if it matched an identifier from the question (from v2, when BM25 exists) **or** its vector score is at least `MinVectorScore` (initial 0.30, calibrated on the dev set in AI-3). If none pass, `ManualSections` is empty: the answer can still give `History` and `General` checks, and every safety step is withheld (G13). | Weak matches never reach the model, so it is not tempted to cite a barely related section. "Not enough evidence" works per chunk instead of all-or-nothing. | A single threshold on the top score that decides whether any manual evidence is sent. |
| G17 | 2026-10-09 | **An embedding failure degrades, it does not fail** (from v1.2 §7.3). If embedding the question fails or times out, AI-01 answers without manual sections (every safety step withheld) and the outcome is logged. | AI-01 works today without manuals; a new dependency must not make it less available than it was. | Reporting the assistant as unavailable. |
| G18 | 2026-10-09 | **Smaller details adopted from v1.2**: `pastCases` holds at most **10** (was 5), the same unit first, then most recent (§6.2); the chunker counts tokens as `ceil(characters / 4)` (§3.4); the knowledge base includes one error code shared by two models with different meanings and one seeded model with work orders but **no** manual (§3.2); evaluation questions carry `expectSafetyWithheld` and `referenceChecks` (§9.1). | Wider history needs more room; a simple, provider-independent token count is accurate enough for a 400-token target; the two knowledge-base cases test the equipment filter and the history/general path; the two fields make the safety and correctness checks in the evaluation explicit. | Five past cases; a model-specific tokenizer. |
| G19 | 2026-10-09 | **`SafetyTerms` extended beyond v1.2 §6.4** (reviewed by the owner on 2026-10-09). English: steam, hydraulic, blade, moving parts. Malay: pengasingan, suis pengasing, litar, litar pintas, kapasitor, nyahcas, buang cas, lepas cas, berputar, wap, wap panas, hidraulik, bilah, renjatan, potong bekalan, suis utama, tiga fasa; isolation only as asingkan bekalan, asingkan kuasa, diasingkan, mengasingkan; lock only as kunci suis, kunci dan tag; current only as arus elektrik, arus tinggi, arus bocor. Loanwords: LOTO, ampere, amp, freon, MCB, DB, breaker. | The seeded equipment includes a steam boiler, a forklift, a band saw and conveyors, and v1.2's Malay list had no words for isolate, discharge, rotating or steam. False positives are acceptable (G13), so a word is narrowed only where it misfires in everyday repair talk: bare `asingkan` also means "put aside" (asingkan skru), `kunci` also means key and spanner (kunci 10mm), `arus` also means airflow (arus udara). Accepted cost: a check saying only "asingkan" or "kunci" relies on the model's `isSafetyStep`. No working technician was available to confirm the wording; "suis pengasing" (isolator switch) was added from formal Malay sources, and "nyahcas" was kept although no technician-written use was found ("discharge" covers the English). | The unreviewed list (bare asingkan, kunci, arus). |
| G20 | 2026-10-09 | **`SafetyTerms` also matches value patterns**, as three fixed regular expressions in the same static class: a voltage (number + `V`/`kV`, e.g. `415V`), a pressure (number + `psi`/`bar`/`kPa`, e.g. `150 psi`) and a refrigerant code (`R` + digits, optional dash and letter, e.g. `R410A`, `R-22`). | The prompt forbids inventing values, so a check containing one is either copied from a cited manual section (kept) or should be withheld anyway. Words alone miss "check 415V across L1–L2". | Words only. |

## Known limitations (accepted)

| Limitation | When it matters | Then |
|---|---|---|
| In-memory vector and BM25 index, per API instance | More than one API instance (another instance can serve results up to 5 minutes old after ingestion), or beyond roughly 50–100k chunks | SQL Server 2025 / Azure SQL `VECTOR` with a DiskANN index behind the same `IVectorStore` |
| Free-text work-order fields (`ProblemDescription`, diagnosis) could contain personal data typed by staff, and AI-01 sends them to the model | Already true for AI-01 before this module | Screening on input, or redaction of those fields |
| Escalation is a message, not a record | A Manager needs to see unanswered questions | A flag or notification on the work order |
| `SafetyTerms` Malay wording was not checked with a working technician (G19) | A technician is available, or evaluation questions in Malay show a missed safety step | Ask how they say "isolate" and "discharge" on site and add what is missing |
| No upload API | People other than developers need to add manuals | `POST` upload into the same ingestion service |
